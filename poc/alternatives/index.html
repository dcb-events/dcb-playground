How it is arranged

Features hold commands. The rail has two levels: a feature ("Course management") is a heading over the commands that make it up. A feature is not a definition of its own — it exists because commands name it, which is why it costs nothing and why an empty one is only remembered until it earns a command.

A command fills the page as a chain of steps — asks for, reads, allowed if, records, changes. Events and state handlers are created and edited in place, so a whole command is built without navigating anywhere.

Entities are reached two ways. Click an entity anywhere — in Reads, in Changes, in the rail — and an inspector slides in beside what you were reading, showing that entity whole and which commands move or consult each property. In Advanced the rail also gains a Model → Entities manager, listing every kind of thing at once with rename, remove, and a flag on properties nothing moves and nothing reads.

Names are written the way you say them. Type "define course" and the model stores DefineCourse; the PascalCase is the schema's business, not yours. The event is suggested from the command by moving the verb behind the thing it acts on — "define course" offers "course defined", "subscribe student to course" offers "student subscribed to course" — and by default it records the same fields the command was given. Everything is shown back as prose; Advanced adds the stored identifier beside it.

A new command is described in the page, not in a dialog. There are no browser prompts or confirms anywhere here — every name is asked for by an inline form that previews what it will be stored as, takes Enter and Escape, and can be cancelled.

Simple hides the machinery. Identifier schemas, custom types, sequences, the derived consistency boundary and the entity manager only appear in Advanced. A new entity still gets its lifecycle, but in Simple the reserved state property is shown as "what state it is in" rather than as an enum.

Known gaps

Sequences and custom types can be referenced but not authored here; renaming a command or an event, and editing an identifier schema, still belong to the current PoC. The feature field a command carries is prototype-only — making it real means allowing it on CommandDefinition in dcb-context.schema.yaml, which today sets additionalProperties: false.

Two earlier alternatives — a board and a guided wizard — were dropped in favour of this one.
