# The DCB notation 11.0

Date: 2026-11-08
Scope: everything the notation and its tooling change in `11.0`, in
implementation order. Built on branch `v11`, which starts from the groups
work (`2ccb98c`).

A set of design decisions reached in discussion, not a primary-source
investigation. Each package links the ticket that holds the full
decision and its evidence. The map is
[Wayfinder: DCB notation extensions for 11.0](https://github.com/dcb-events/dcb-events.github.io/issues/96).

Origin: two migrations to the notation, a customer portal already on DCB
and a courses app on stream-based Event Sourcing, plus a redesign of the
courses app (`courses-simple.dcb`). Background research:
`2026-11-06-experimental-constructs-inventory.md` and
`2026-11-06-event-time-in-dcb.md` (local branches
`research/experimental-constructs`, `research/event-time`).

## Status

Implemented on `v11`: packages 1–10. Open: 11 (alongside each), then
acceptance.

Package 8 holds `set`, `append` and `remove` to nominal types;
`increment` and `decrement` are arithmetic and mix number types, as a
command's `+` and `-` do. Package 9 stores a scenario written as code
as written, an omitted property unspecified; the page's save still
spells out null for what a draft left unset. An omitted tag, and a
value outside its type, make the run an error (broken), not a refusal
on the write path. Package 10 stores the notes as `assumptions`,
`externalRules` and `unresolved` (lists), `isDeprecated` and
`isSensitive`, and the model's description as a log event of its own;
a grouped projection carries a description and notes. The "nothing
emits this event" advisory holds every event, scenario-given or not:
the shipped models emit all of theirs.

Package 7 also lets a collection function compute over a record's
field, `sum(Reservation(courseId, *).seats where value.expiresAt >
now)`, which the decided example needs: a sum over a record held no
number. A command's arithmetic is `+` and `-` only, left to right; no
datetime minus datetime and no negative duration.

Visual editing of branches, loops, conditional handlers and collection
functions is a follow-up: the pages show them read-only with "Edit in code".

## Standing principles

- **A feature must earn its place for greenfield models too.** Migration
  cost is evidence, not justification.
- **Decisions computed outside the model are out of scope.** A layer
  around the commands creates identifiers, authenticates users, calls
  external systems and checks external capabilities, then dispatches
  commands. External handlers (email, imports) and external triggers
  (cron, expiry jobs) are that layer calling commands.
- **One condition vocabulary.** `if` branches between steps (handlers,
  loops, commands); `where` filters a collection. Both take the same
  conditions.
- **"Aggregate" means only the DDD / stream-based aggregate.** It is not
  a notation concept. See `GLOSSARY.md`.

## Packages, in order

The order follows dependencies:
- 1 and 2 shrink the language before anything is added.
- 3 lays down the evaluation model and the `if` grammar that 4 and 6 reuse.
- 5 comes before 6, because `for each` iterates open reads.
- 7 to 10 are independent.
- 11 accompanies every package. The reference test already forces
  documentation per construct.

All packages ship as one major, `11.0` (`/v11.json`).

### 1. Groups replace entities

[Verdict on the remaining experimental constructs](https://github.com/dcb-events/dcb-events.github.io/issues/111);
`2026-10-28-groups-replace-entities.md`;
`2026-10-28-lifecycles-for-enum-projections.md`.

- `group Course (tag courseId: CourseId) { projection capacity … }` owns
  its projections, which inherit its one tag. It has no consistency
  meaning. A grouped projection is read as `Course(courseId).capacity`,
  or through an alias.
- Lifecycles stop being a construct. A Lifecycle tab per projection derives
  a state machine for enums and booleans, and the movements for other
  values.
- `excluding` and write coverage are removed.
- On import, 10.x entities convert to groups (`groupsFromEntities`). An
  `excluding` that changed a rule's meaning must refuse the import rather
  than silently drop the exclusion.

### 2. Removals

[Verdict on the remaining experimental constructs](https://github.com/dcb-events/dcb-events.github.io/issues/111),
[Guarded emits, optional reads and OR](https://github.com/dcb-events/dcb-events.github.io/issues/104).

- **Removed:**
  - scripted projections (including inside groups), together with the
    import gate (`envelopeHasScript`) and `?safe` (`setScriptsDisabled`)
  - `currentValue`
  - guarded emissions (`emit … when …`)
  - optional reads (`alias x? = …`, `isOptional`)
- An import of a 10.x document using scripts or `currentValue` is refused,
  with a message naming the construct.
- Shipped `content-decisions-scripted` is dropped.
- The experimental flag stays, as the mechanism for staging future work.

### 3. Commands: top-down, branches, lazy reads, `or`

[Guarded emits, optional reads and OR](https://github.com/dcb-events/dcb-events.github.io/issues/104).

```
command EndContractShare(shareId: ShareId, actor: CustomerId) {
  require ShareActive(shareId) is true else reject "Share is not active"
  if ShareOwner(shareId) == actor => emit ContractShareEnded { shareId, …, reason: "ownerEnded" }
  else if ShareInvitee(shareId) == actor => emit ContractShareEnded { shareId, …, reason: "inviteeEnded" }
  else => reject "Customer is not owner or invitee of this share"
}
```

- **Evaluation order:** a command body runs top-down, in written order,
  with `require` and `if` interleaved. Any `reject` aborts the command
  with no events. The emits gathered along the way form one append.
- **Branches:** `if … => <stmt>  else if … => <stmt>  else => <stmt>`.
  Separate `if`s all run, and an `else` chain runs only its first match. A
  branch body is one statement (`emit`, `reject`) or a block `{ … }`
  (`require`, `emit`, `if`, `for each`).
- **`require c else reject "m"`** stays, as shorthand for
  `if not c => reject "m"`.
- **Lazy reads:** a read is evaluated when first needed, so a read guarded
  by an earlier `require` / `if` never happens. A null tag on a read that
  is reached stays an error.
- **Boundary:** at runtime the append condition covers only the reads
  made. `check` / `conflicts` show the static boundary: every read any run
  might make.
- **`or`** in rules, `if` and `where`. `and` binds tighter, and
  parentheses are allowed.
- **Checks:**
  - Inside `if x is not empty`, and after `require x is not empty`, an
    optional parameter counts as present.
  - One scenario is owed per `emit` branch and per `reject`.

### 4. Conditional handlers

[Conditional handlers](https://github.com/dcb-events/dcb-events.github.io/issues/99).

```
projection Balance (tag accountId: AccountId): Cents = 0 {
  on MoneyTransferred {
    if event.data.from == accountId => decrement event.data.amount
    if event.data.to == accountId => increment event.data.amount
  }
}
```

- **Form:** `on E => op` stays. `on E { if … => op  else if … => op  else => op }`
  adds branches, with the same matching rules as in commands. Each branch
  holds one operation.
- **Conditions:** `event.data.<path>` against the projection's own tag
  values or literals, using `==`, `!=`, `and`, `or`. A condition never
  reads other projections or the projection's own state.
- **Boundary:** unchanged, because the condition filters the fold, never
  the query.
- **The "tag type carried twice" refusal** clears when every branch
  handling that event tests one of the carrying fields.

### 5. Record values, open tags, collection functions

[Keyed projections with collection functions](https://github.com/dcb-events/dcb-events.github.io/issues/102).

```
projection ReservationSeats (tag courseId: CourseId, tag reservationId: ReservationId): Seats = 0 {
  on SeatsWereReserved => set event.data.numberOfSeatsReserved
  on SeatReservationWasCancelled => set 0
}
derived projection CourseSeatsReserved (tag courseId: CourseId): integer {
  sum(ReservationSeats(courseId, *))
}
```

- **Open tags:** `P(x, *)` reads every instance of `P` matching the bound
  tags, and at least one tag stays bound.
  - **Present instances:** an instance at the projection's initial value
    is absent, so setting the initial value acts as delete.
  - **Boundary:** the handled types, with only the bound tags.
  - **Where an open read may appear:** only in a collection function or
    as the source of `for each`.
- **Collection functions:** `count`, `sum`, `min`, `max`, `average`, `any`
  and `all`, each with an optional `where` over `value` / `value.field`,
  parameters and literals. A `where` never reads projections.
  - **On an empty collection:** `sum` and `count` give 0, `min`, `max`
    and `average` give null, `any` gives false and `all` gives true.
- **Record values:** a projection may hold a record if every handler
  replaces it whole. `P(x).field` reads a field anywhere a value is
  allowed. Composite state, where handlers set individual fields, stays
  refused.
- **Lists:** list projections stay. Turning them into open-tag booleans is
  a later candidate, out of 11.0.

### 6. Fan-out emits

[Fan-out emits](https://github.com/dcb-events/dcb-events.github.io/issues/103).

```
for each shareId in ShareActiveAsOwner(customerId, *) => emit ContractShareEnded { shareId, … }
for each notificationId in notificationIds {
  if UnreadNotificationIds(customerId) contains notificationId => emit NotificationWasMarkedAsRead { … }
}
```

- **Sources:** an open-tag read, a list projection or a list parameter.
- **Loop variable:** named explicitly, `(a, b)` for two open tags. An open
  read also gives `value`.
- **Body:** `=> emit …`, or branches with one `emit` each. Loops have no
  `where`. Reads per element are allowed and add one boundary line each.
- **Behaviour:**
  - Zero elements emit nothing.
  - Elements run in source order: list order, or the order of each
    instance's first event.
  - Nested loops are refused.

### 7. Time

[Time](https://github.com/dcb-events/dcb-events.github.io/issues/106).

- **No event timestamp.** The DCB spec has none, which may be revisited
  if it ever gets one. Domain time is event data.
- **`now: datetime`** is an ordinary parameter supplied by the outer
  layer, so scenarios need no clock.
- **Built-in `datetime`:** RFC 3339 with an offset, compared as instants.
- **Built-in `duration`:** literals `30s`, `15m`, `24h`, `7d`, where `d`
  is exactly 24h.
- **Arithmetic:** `datetime ± duration` in rules, emits and derived
  projections.
- `replay` validates both types.

### 8. Strict handler assignments

[Non-tagging identifiers and tag conversions](https://github.com/dcb-events/dcb-events.github.io/issues/105).

- **Strict:** a handler's `set` is held to nominal types, like reads and
  emits.
- **No casts:** there is no cast, and `T(value)` is the spelling should
  one ever be needed.
- **No tag conversions:** role tag types are unnecessary with conditional
  handlers.
- **No `ref`:** a property of a tag type stays a tag, so migrations
  backfill the tag. Revisit as `@untagged` if more migrations hit it.

### 9. Partial scenarios and scenario fixes

[Scenario fixtures](https://github.com/dcb-events/dcb-events.github.io/issues/108).

- **Partial events and commands:**
  - Scenarios may omit non-tag properties in `given`, `when` and `then`.
    Tags are always given.
  - Reading an omitted property is a scenario error, so the scenario
    reveals its dependencies.
  - `then` matches only the listed fields.
- **Best practice:** omit every property a scenario doesn't depend on.
- **No fixtures for now.** If they come later, they are scoped per
  `scenarios` block.
- **Two fixes from the handoff's table:**
  - Type constraints are enforced on the scenario values given.
  - Optional list properties are allowed, with `null` meaning absent.

### 10. Descriptions, notes, `@sensitive`

[Stored notes and external rules](https://github.com/dcb-events/dcb-events.github.io/issues/109),
[PII-safe tag values](https://github.com/dcb-events/dcb-events.github.io/issues/101).

- **Descriptions:** a `///` doc comment is a stored description, on every
  definition and on the model.
- **Notes:** `@assumption("…")`, `@unresolved("…")`, `@external("…")` and
  `@deprecated`, on definitions only. They are documentation only and
  never change a boundary.
- **`check`:**
  - "Model is incomplete: N unresolved" (`--strict` fails).
  - An advisory when a `@deprecated` event is emitted.
  - The missing "nothing emits this event" advisory, suppressed by
    `@deprecated`.
  - External rules and assumptions listed per command.
- **`@sensitive`** goes on tag types and value types only.
  - On a tag type, the store must not render the plain value; the adapter
    chooses the hash or HMAC.
  - The language gets no hash or normalisation functions. The outer layer
    normalises, and the model states a `pattern`.
- These are fields older readers can ignore, so a minor change on their
  own.

### 11. Documentation and the skill

Accompanies each package. Topics beyond the new constructs:

- **Already supported, now documented** ([Tag paths and tag each on plain lists](https://github.com/dcb-events/dcb-events.github.io/issues/100)):
  - nested record tags, `field: Record tag sub`
  - plain-list tags, `tag xs: T[]`
- **No open records:** an identifier inside an opaque payload stays
  untaggable.
- **External decisions** ([Boundary-only reads](https://github.com/dcb-events/dcb-events.github.io/issues/107)):
  - No boundary-only reads, and no revision pattern.
  - An external check sits in the layer around the commands, and the
    command needs no result parameter.
  - For a race between check and append, in order: accept it, fold the
    part that matters into an ordinary rule, or widen the append condition
    in the implementation.
- **Reactions** ([Reactions as documentation](https://github.com/dcb-events/dcb-events.github.io/issues/110)):
  - No construct.
  - A chain inside the model becomes one command with one append.
  - External handlers and triggers are the outer layer calling commands.
- **Conversion guidance** (`from-event-sourcing.md`, `redesign.md`,
  Gotchas):
  - updated for each package
  - tag backfill over `string` workarounds
  - omitting irrelevant scenario properties

## Integration

- **Branch:** `v11` in the playground, one PR per package. It merges to
  `main` together with the website's pin bump, as AGENTS.md requires for a
  major. The website's notation pages follow then.
- **Versions:** `MODEL_VERSION` is `11.0` on the branch already.
  `EVENT_LOG_KEY` is bumped once, at the merge to `main`: v24 on the
  branch, plus one more if a stored shape changes after it.
- **Acceptance:** as the last step of `v11`:
  - Re-express copies of `customer-portal.dcb` and `courses.dcb`, and
    count the removed workarounds and unresolved items against the
    migration handoff.
  - Run `replay` against the courses log. Never edit the originals.

## Out of scope

- The public notation pages on dcb.events, which follow implementation.
- Protecting personal data in event payloads (erasure, crypto-shredding).
